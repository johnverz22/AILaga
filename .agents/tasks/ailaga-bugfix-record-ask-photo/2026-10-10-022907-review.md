# AILaga bug fixes: Record permission, Ask init, Photo mode guard

Three runtime behavioral bugs were fixed in four Dart files. On Android 6+, the microphone permission dialog never appeared because `hasPermission()` (check-only) was called instead of `Permission.microphone.request()`. The Ask engine called `FlutterGemma.initialize(...)` lazily inside `ensureLoaded()`, violating the flutter_gemma 1.11.3 contract that this call must happen in `main()` before `runApp`; a secondary loop also re-ran `.install()` after every idle unload. For Photo Analyze, the Process button remained enabled in Basic mode, routing through `NullEngine.extractFromImage()` which throws `AiUnavailable` — caught as a generic "Something went wrong" with no actionable message.

Watch for: **(confirmed)** The `_modelInstalled` flag in `GemmaLiteRtEngine` resets on a cold restart — after a process kill and relaunch, `_modelInstalled` will be `false` and `FlutterGemma.hasActiveModel()` will also be false, so `install()` runs again. This is correct behavior for a cold start, but the flag name implies it persists across restarts when it doesn't — only a runtime concern, not a regression.

**Verdict**: APPROVED

---

## High-level view

The microphone fix moves permission acquisition into `VoiceCaptureService.ensurePermission()` — first a lightweight `hasPermission()` check, then `Permission.microphone.request()` if that returns false. `start()` already called `ensurePermission()`, so the UI call path is unchanged. The OS dialog now appears on first tap.

`FlutterGemma.initialize()` is now in `main()`, wrapped in a silent try/catch so simulator environments don't crash. The `_initialized` flag in `GemmaLiteRtEngine` has been renamed `_modelInstalled` and repositioned to gate only the `.install()` call, not the `initialize` call. After an idle unload, `_model` is nil but `_modelInstalled` is true, so re-entering `ensureLoaded()` skips install and goes straight to `getActiveModel()`.

In `SnapCaptureScreen`, the `isBasic` guard that was already on the Camera/Gallery buttons is now also applied to the Process button. An amber explanatory container appears between the image preview and the button when Basic mode is active. Camera permission is now requested explicitly via `permission_handler` before calling `snapPhoto()` — denial shows a SnackBar; the gallery path is untouched since `image_picker` handles that itself. The `_processPhoto()` catch distinguishes `AiUnavailable` from other errors to give an actionable message.

The four changed Dart files (`main.dart`, `voice_capture_service.dart`, `gemma_litert_engine.dart`, `snap_capture_screen.dart`) are surgically targeted. No excluded screens, nav structure, button positions, Today screen, Reports screen, or notification screen were touched.

### Microphone permission request in VoiceCaptureService

The root bug: `ensurePermission()` originally returned `_recorder.hasPermission()` — a check, not a request. On first launch, that returns `false`, `start()` throws `AiUnavailable`, and the OS permission dialog is never shown. The fix expands `ensurePermission()` to call `Permission.microphone.request()` when `hasPermission()` returns false, then re-evaluates. `start()` calls `ensurePermission()` unchanged. The voice capture screen's `_toggleRecording()` calls `start()` and catches `AiUnavailable` to show "Microphone not available" — that error path is now only reached after a genuine denial, not a missing request.

### FlutterGemma.initialize placement and re-install loop

`FlutterGemma.initialize(inferenceEngines: [LiteRtLmEngine()])` is now in `main()`, ahead of `runApp`, wrapped in a try/catch that silently swallows failures so the app still starts on environments without LiteRT (emulators, test hosts). The `flutter_gemma_litertlm` import was removed from `gemma_litert_engine.dart` as no longer needed — confirmed clean by `dart analyze`.

In `ensureLoaded()`, the `_modelInstalled` flag gates only the `.install()` call with `!_modelInstalled && !FlutterGemma.hasActiveModel()`. After an idle unload, `_model` is nil but `_modelInstalled` is true, so re-entry skips install and goes straight to `getActiveModel()`. This is the re-install loop fix. The double-check against `hasActiveModel()` also guards the case where the model was registered in a prior `ensureLoaded()` call within the same process lifetime but the flag hasn't been set (e.g., the first call).

### Process button Basic-mode guard and camera denial feedback

The `isBasic` guard applied to the Process button is `onPressed: isBasic || _processing ? null : _processPhoto`. The amber explanatory container appears only when `isBasic && _photo != null`, directly above the button — same visual style as the existing banner at the top of the screen. No layout structure or button positions changed (confirmed by reading the diff: only the `onPressed` value and one conditional `Container` insertion).

The camera permission request runs before the `_snapService.snapPhoto()` call. Denial shows a SnackBar; the function returns early. After the `_pick` call, `input == null && camera` triggers a "Could not open camera" SnackBar only for the camera path, so gallery cancel is silent (expected UX for picker dismissal). The `_processPhoto()` catch now branches on `e is AiUnavailable` for a targeted error message.

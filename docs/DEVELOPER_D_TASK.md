## Architecture Principles

1. **Offline-first is non-negotiable.** All features must work without internet. Cloud sync is additive, not required.
2. **Local Drift DB is the source of truth.** Supabase mirrors it; it does not replace it.
3. **Auth is optional.** The app works without signing in. Auth enables cloud backup and multi-device sync.
4. **No personal data in Firebase.** Firebase is Auth-only. All health data goes to Supabase.
5. **Row-Level Security (RLS) required.** Every Supabase table must have RLS enabled so users only see their own data.

**Interface:**
```dart
enum SyncDirection { upload, download, bidirectional }
enum SyncStatus { idle, syncing, success, error, disabled }

class SyncResult {
  final SyncStatus status;
  final int recordsUploaded;
  final int recordsDownloaded;
  final String? errorMessage;
  final DateTime syncedAt;
}

abstract class SyncService {
  /// Current sync status — stream for real-time UI updates.
  Stream<SyncStatus> get statusStream;

  /// Sync all local data to Supabase. Requires auth.
  Future<SyncResult> syncAll(String firebaseUid);

  /// Upload a single record type (use after any local write).
  Future<void> syncTable(String tableName, String firebaseUid);

  /// Download remote data to local DB (for multi-device restore).
  Future<SyncResult> downloadAll(String firebaseUid);

  /// Returns the last successful sync timestamp, or null.
  Future<DateTime?> getLastSyncTime();
}
```

**Conflict resolution — last-write-wins:**
- Compare `updated_at` timestamps between local and remote
- Whichever record has the newer `updated_at` wins
- For medication occurrences: local status always takes priority (caregiver confirmation is authoritative)

**Sync logic per table:**
```dart
// Upload pattern (same for all tables):
Future<void> _uploadTable<T>({
  required String tableName,
  required String firebaseUid,
  required List<Map<String, dynamic>> rows,
}) async {
  if (rows.isEmpty) return;
  await Supabase.instance.client
      .from(tableName)
      .upsert(rows.map((r) => {...r, 'firebase_uid': firebaseUid}).toList());
}
```

#### Task D11: Automatic Sync Triggers
**File:** `lib/services/sync/sync_trigger_service.dart`

Trigger sync automatically at these points:
- [x] On app foreground (app lifecycle `resumed`) — throttled to once per 5 minutes
- [x] After any successful write operation (create/update/delete) — debounced 10 seconds
- [x] On explicit user tap in Settings → "Sync Now"

```dart
class SyncTriggerService {
  final SyncService _syncService;
  DateTime? _lastAutoSync;

  void onAppResumed(String firebaseUid) {
    final now = DateTime.now();
    if (_lastAutoSync == null ||
        now.difference(_lastAutoSync!).inMinutes >= 5) {
      _lastAutoSync = now;
      _syncService.syncAll(firebaseUid);
    }
  }
}
```

- [x] Wire app lifecycle to `onAppResumed`
- [x] Only trigger if user is signed in
- [x] Errors from background sync are silently logged (no user-facing error for background sync)

**Acceptance:** Sync triggers on foreground. Debounce prevents sync spam. Background sync errors don't surface to user.

4. **Merge strategy:** A and B merge first. You rebase your auth/sync branch on top of their work
5. **Offline-first is a hard constraint** — any change that breaks offline usage is a blocker
6. **Test without network** before every merge — `flutter run` in airplane mode must reach home screen
7. **Supabase anon key is intentionally public** — security comes from RLS, not key secrecy. Document this clearly in code comments
